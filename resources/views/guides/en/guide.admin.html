Administrator Guide

As an administrator you are the operational lead of one or more projects: you configure the project, register the families, accompany the process and run the lottery. This guide walks that path in order, from a freshly created project to the published result.

Before you start

  • Projects are created by the platform team (superadministration), which also designates you as administrator. If you need a new project, contact them.
  • You can manage several projects; the application works on one selected project at a time (pick it under Projects if you manage more than one).
  • Navigation lives in the left sidebar (Dashboard, Lottery, Families, Members, Gallery, Events, Documents, Projects); on mobile, tap the menu button to expand it. Creating entities — types, units, families, members, events — happens through the + (Quick Actions) button, top right. The Dashboard summarizes the project's state by section.

Setting up a project

The natural order to get a project ready for its lottery:

1. Define the unit types

A unit type groups homes that are comparable with each other: "two bedrooms", "three bedrooms", "studio". Each family will compete only for units of its type, so define the types first.

2. Load the units

Each unit is a concrete home, with its identifier (the name or code the cooperative knows it by, e.g. "A-101") and its type. The identifier must be unique within the project.

3. The plan (optional, recommended)

Every project has a plan where you can draw and place the units and common spaces, dragging elements into position. Families find it enormously helpful when deciding their preferences: they see where each unit is before ranking them.

4. Register the families

Create each family with its name and its unit type (set this carefully: it determines which units the family competes for). Then invite at least one member of each family: they get an email with the link to complete their registration. From there, each member can invite the rest of their own family — you don't have to load everyone yourself.

5. Events and communication

Under Events you can publish meetings and assemblies (on-site or online), with optional attendance confirmation. The lottery event is created automatically with the project: you don't create or delete it; edit it to set or change its date and description (while it hasn't been executed). In the Gallery and Documents, anyone in the project can share images, documents and audio.

The lottery

Before running it

  • Check that all families are registered, each with its correct type.
  • Check that all units are loaded.
  • Families register preferences until the moment of execution; agree on the date with the cooperative and publish it in the lottery event.

Execution

From Lottery, run it when the process is ready. When you do:

  • Preferences lock automatically.
  • The system draws per unit type (each family competes for the units of its type) and assigns all units at once, first guaranteeing the least-favored family does as well as possible, then maximizing overall satisfaction.
  • If the number of families and units doesn't match, the system warns you and asks for confirmation before continuing.
  • If something fails, the lottery returns to its previous state (preferences unlock) and you can retry; the error is recorded.

Afterwards

The result is final: it cannot be edited or negotiated, and it is visible to the whole project. Every step of the execution lands in a permanent audit log. Only in exceptional situations (e.g. a data error discovered later) can the superadministration invalidate the whole execution so the data can be fixed and the lottery run again.

Ongoing management

  • Families, members and units can be edited at any point before the lottery; if a change affects registered preferences (a new unit, a type change), the families' lists adjust automatically.
  • Deleting by mistake is not catastrophic: families, members and content can be restored.
  • The project's activity log records general activity.

Your account

Your personal settings (profile, photo, email — with verification —, password, appearance and themes) work the same as for any user: they're behind your name, at the bottom of the sidebar. The details are in the Member Guide, which is also the best way to know the application as families see it.
