Superadministrator Guide

The superadministrator is responsible for the platform. This role exists for three things nobody else can do; for everything else, a superadministrator can perform any action a regular administrator can, on any project — this guide covers what's exclusive and refers to the Administrator Guide for the rest.

What only a superadministrator can do

1. Create projects

Project creation is reserved to this role as a deliberate anti-abuse measure: it prevents anyone from mass-creating projects or accounts. When creating a project (from Projects or the + Quick Actions button), set its name, description and organization.

2. Designate administrators

A freshly created project needs at least one administrator: create and invite one (they receive the registration link by email) or assign the project to an existing administrator. A project can have several administrators, and an administrator can manage several projects. From there, setting the project up is the administrator's job (see their guide).

3. Invalidate a lottery execution

The lottery result is final by design. The only way out, meant for exceptional situations — for example, a data error discovered after running it, such as a family that was never registered — is for a superadministrator to invalidate the whole execution from the Lottery section:

  • The assignment is undone and preferences become editable again.
  • Nothing is lost: the invalidated execution remains consultable, and the invalidation itself is recorded in the audit log with your identity.
  • Once the data is fixed, the administrator can run the lottery again.

It is a last-resort action: use it judiciously and in coordination with the cooperative.

Everything else

For project operation — unit types, units, plan, families, invitations, events, running the lottery, ongoing management — follow the Administrator Guide: everything described there is available to you too, on any project. Your personal account settings are described in the Member Guide.

How this role is granted

The superadministrator role is not assigned from the application: it is configured in the platform's deployment (a list of authorized email addresses). This is deliberate — the most powerful role cannot be granted by mistake or abuse from the interface itself.
